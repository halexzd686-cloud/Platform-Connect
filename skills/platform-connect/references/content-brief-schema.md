# Content brief schema

Create this brief once. Every platform version must derive from it.

Before creating it, complete source intake using
`source-intake.md` as routed from `SKILL.md`.

```yaml
summary: faithful two-to-four sentence summary
core_thesis: the single claim the content must deliver
author_stance: what the author supports, rejects, or remains uncertain about
audience: people whose problem or decision the source addresses
audience_need: the practical question the content helps answer
tone: source tone and any requested adjustment
facts:
  - source-backed names, numbers, dates, examples, and quotations
protected_claims:
  - statements that must not be strengthened, weakened, or reversed
content_units:
  - hook-worthy conflict or question
  - explanation, example, method, or conclusion
uncertainties:
  - ambiguous or unsupported statements requiring review
keywords:
  - stable semantic anchors shared by copy and visuals
```

## Extraction rules

- Prefer source wording for facts and protected claims.
- Separate a personal opinion from a verified fact.
- Do not convert correlation into causation or advice into a guarantee.
- If the source has multiple possible theses, identify the primary one and list alternatives as content units.
- If localization is requested, keep proper nouns and source evidence traceable to the original.
